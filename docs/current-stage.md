# Текущий этап проекта

## 1. Краткая характеристика

Проект «Распределённая система мониторинга Linux-узлов вычислительного кластера» находится на этапе функционального прототипа с завершённым демонстрационным контуром. Реализована цепочка от сбора метрик на агенте до отображения данных в веб-интерфейсе.

Текущий результат можно представить как минимально целостную систему мониторинга:

```text
сбор -> доставка -> хранение -> API чтения -> визуализация
```

## 2. Что реализовано

### Агент

- Сбор CPU-метрик с общей загрузкой и детализацией по ядрам.
- Сбор показателей оперативной памяти.
- Сбор статистики по смонтированным файловым системам.
- Сбор сетевых счетчиков и расчет RX/TX в bytes/s.
- Определение стабильного `host_id`.
- Формирование JSON-снимка `Metrics`.
- Отправка снимка на сервер по HTTP.

### Сервер

- HTTP-эндпоинт для приема метрик.
- Минимальная валидация входящих снимков.
- Подключение к PostgreSQL через `pgxpool`.
- Регистрация устройств в таблице `devices`.
- Сохранение истории в таблице `metric_snapshots`.
- API чтения для списка узлов, последнего снимка и истории.
- Статическая раздача веб-интерфейса.

### Хранилище

- Таблица `devices` хранит уникальные `host_id`, время первого появления и время последней активности.
- Таблица `metric_snapshots` хранит историю снимков с привязкой к устройству.
- Полный снимок сохраняется в `raw` JSONB.
- Отдельные JSONB-поля сохраняют CPU, память, диск и сеть.

### Веб-панель

- Отображение зарегистрированных узлов.
- Расчет и отображение online/offline.
- Просмотр последнего снимка выбранного узла.
- Графики CPU, памяти и сетевого трафика.
- Таблица последних измерений.
- Автообновление с интервалом 2 секунды.

### Docker Compose

- PostgreSQL 16.
- Сервер приложения.
- Три демонстрационных агента с `HOST_ID=node-1`, `node-2`, `node-3`.

## 3. Что считается стабильным на текущем этапе

- JSON-контракт `Metrics`.
- Эндпоинт приема метрик `POST /api/v1/metrics`.
- Модель хранения `devices` и `metric_snapshots`.
- Основной сценарий запуска через Docker Compose.
- Веб-панель как основной интерфейс демонстрации.

## 4. Что находится вне текущего этапа

- Аутентификация агентов.
- Авторизация пользователей.
- Шифрование трафика средствами приложения.
- Очередь доставки метрик.
- Политика повторной отправки на стороне агента.
- Алертинг.
- Политика хранения исторических данных.
- Горизонтальное масштабирование сервера.
- Ролевая модель доступа.

## 5. Демонстрационная ценность

Проект демонстрирует:

- проектирование единого контракта метрик;
- разделение ответственности между агентом, сервером и интерфейсом;
- сбор Linux-метрик из системных источников `/proc`;
- сохранение снимков, пригодных для анализа временных рядов, в PostgreSQL;
- отображение текущего состояния распределённых узлов;
- воспроизводимый стенд для проверки и презентации.

## 6. Рекомендуемая формулировка для выступления

Проект «Распределённая система мониторинга Linux-узлов вычислительного кластера» является прототипом системы наблюдаемости для кластерной Linux-инфраструктуры. На текущем этапе реализован полный путь данных: агент собирает системные метрики, передает их на сервер по HTTP, сервер сохраняет снимки в PostgreSQL, а веб-интерфейс отображает состояние узлов и историю ключевых показателей. Основной акцент текущей версии сделан на архитектуре, контракте данных и воспроизводимой демонстрации, а промышленные функции безопасности, отказоустойчивой доставки и алертинга вынесены в дальнейший план развития.

## 7. Следующие направления развития

- Добавить аутентификацию агентов и подпись запросов.
- Добавить механизм повторной отправки и локальный буфер на стороне агента.
- Ввести политику хранения и очистку старых снимков.
- Добавить алертинг по пороговым правилам.
- Расширить API фильтрами по времени.
- Добавить миграционный инструмент, не зависящий от первичной инициализации PostgreSQL volume.
- Подготовить промышленную конфигурацию с TLS и внешним обратным прокси.
